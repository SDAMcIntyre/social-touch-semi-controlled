# Plan: Heatmap Enhancements — Total Points, Log Axes, White Background

**Date:** 2026-03-17
**Author:** Basil Duvernoy
**Status:** Active
**Branch:** `feature/unified-touch-analysis-pipeline`

---

## Overview

Improve per-session touch density heatmaps generated by the unified pipeline: display total single-touch count in the title, default to logarithmic (geometric) axis binning, and render empty cells with a white background for visual clarity.

## Problem Statement

The current per-session heatmaps lack key information and visual polish:
1. **No total count in title** — users cannot see at a glance how many single touches a session contains.
2. **Linear axis binning** — data with skewed distributions (e.g. velocity, force) compresses most points into a few bins; geometric binning spreads them more evenly.
3. **Grey masked cells** — seaborn's default mask color makes it hard to distinguish "no data" from low-count bins; white is the conventional "absence" colour.

## Goals

### In Scope
1. Append `| Total Points: X` to every per-session heatmap title
2. Switch default axis binning from linear (`np.linspace`) to geometric (`np.geomspace`) in the pre-computed global edges and in the reporter call
3. Set axes background to white so masked/zero-count cells render as white

### Out of Scope
- Changes to the population-level heatmaps in `generate_population_heatmaps`
- Adding a UI toggle for log vs linear axis in the GUI
- Changing colour map or LogNorm colour scaling behaviour

## Success Criteria

- [ ] Heatmap title reads `Touch Density — <session_id> | Total Points: <N>`
- [ ] Axis bin edges use geometric spacing for positive data (linear fallback for non-positive)
- [ ] Cells with zero touches appear white, not grey
- [ ] Existing heatmap layout (N×2 grid, tap/stroke columns) unchanged

---

## Technical Design

### Approach

Minimal targeted edits in two files: the orchestrator (`unified_pipeline.py`) for edge computation and the reporter (`reporting.py`) for rendering. No new modules or classes needed.

### Alternatives Considered

| Approach | Pros | Cons | Decision |
|----------|------|------|----------|
| Edit existing methods in-place | Minimal diff, no API changes | None significant | **Chosen** |
| Add new `log_heatmap` method | Clean separation | Duplicates most of the existing method | Rejected |
| Make log default configurable via YAML | Flexible | Over-engineering for current need | Rejected (future work) |

### Architecture Changes

None. Only parameter values and a few lines within existing functions change.

## Implementation Plan

### Phase 1: Log axis binning in orchestrator
**Goal:** Pre-compute geometric bin edges so all per-session heatmaps share log-scaled axes.

- [ ] Replace `np.linspace` with `np.geomspace` (positive-data guard + linear fallback) in `_generate_session_heatmaps`
- [ ] Change `log_axis=False` to `log_axis=True` in the `reporter.generate_touch_density_heatmap(...)` call

**Files Modified:**
- `code/src/analysis/touch_analytics/unified_pipeline.py` — `_generate_session_heatmaps` (~lines 486-528)

**Dependencies:** None

### Phase 2: Title and background in reporter
**Goal:** Show total touch count in title; white background for empty cells.

- [ ] After the plot cache loop, compute `total_points` by summing counts for one y-row across interaction types
- [ ] Append `| Total Points: {total_points}` to `fig.suptitle`
- [ ] Add `ax.set_facecolor('white')` before each `sns.heatmap` call

**Files Modified:**
- `code/src/analysis/touch_analytics/reporting.py` — `generate_touch_density_heatmap` (~lines 390-432)

**Dependencies:** None (can be done in parallel with Phase 1)

## Risks and Mitigations

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|
| `np.geomspace` fails on non-positive data | Med | Low | Guard clause filters to positive values; linear fallback on failure |
| Total count double-counts across y-rows | Low | Low | Sum only from `y_idx=0` row to count each touch once |
